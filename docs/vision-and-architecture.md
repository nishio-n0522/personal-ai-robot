# Personal AI Robot — Vision & Architecture

更新: 2026-10-17

## 最上位のビジョン

**アイアンマンのトニー・スタークと J.A.R.V.I.S. のように、人間とAIが自然な対話を通じて継続的に協業する、個人用のパーソナルAIを構築する。**

かわいいAIペットロボットは、そのAIと人間をつなぐ**物理的なインターフェース／身体**である。単なる雑談ロボットではなく、相談・共同設計・作業依頼・進捗確認・成果物レビュー・修正依頼を一貫した対話で行う。

## 設計原則

1. **人格と実行能力を分離する。** 小型ローカルLLMは会話、キャラクター性、意図理解、依頼の窓口を担う。高度な推論や専門作業は別のモデル・エージェントへ委譲する。
2. **人格・記憶をモデルに依存させない。** 会話履歴、ユーザー設定、プロジェクトの状態、長期記憶は永続化し、LLM交換後も継続できるようにする。
3. **分散実行を前提とする。** Windows、Mac、サーバー、クラウドを「作業ノード」として登録し、能力・負荷・可用性に応じて仕事を割り当てる。将来のハード追加はノード追加で対応する。
4. **非同期・継続的な協業を支える。** タスクを受け付け、進捗と成果物を追跡し、途中で人間の追加指示や方向転換を受けられるようにする。
5. **安全性と制御可能性を優先する。** 権限を最小化し、ファイル削除、外部公開、購入・課金、秘密情報へのアクセスなど重要操作には明示的な承認を設ける。実行ログ・コストを残す。
6. **ロボットの自然な動作をLLMだけに依存させない。** まばたき・視線追従・サーボ制御などリアルタイム処理は専用ロジックで実装し、LLMは高レベルの意図・感情・行動指示を担当する。

## 論理アーキテクチャ

```text
人間
  ⇅ 音声・カメラ・表情・動作
AIペット（物理インターフェース）
  ⇅
パーソナルAIコア
  ├─ 会話・人格（小型ローカルLLM）
  ├─ 長期記憶・プロジェクト文脈
  ├─ タスク受付・計画・進捗管理
  ├─ ルーティング・権限・承認
  └─ ツール／エージェント接続
       ├─ Windowsワーカー：Blender / DaVinci / CUDA
       ├─ macOSワーカー：Xcode / iOSゲーム開発
       ├─ 自宅サーバー：API / DB / キュー
       └─ クラウドAI：高度な推論・コード生成
```

コアはジョブID、状態、実行先、成果物の参照、失敗・再試行情報を管理する。エージェントには限定されたツールを公開し、LLMの自然言語出力を無検証でシェル実行しない。

## 代表的な利用シナリオ

「昨日のゲームのプレイ動画から短い広告を作って」とAIペットに話す。

1. ローカルLLMが依頼を解釈し、必要な条件を確認する。
2. オーケストレーターが動画制作ワーカーにジョブを登録する。
3. ワーカーが素材を参照し、スクリプト可能な範囲で編集・レンダリングを実行する。必要なら高度なモデルへ演出案を依頼する。
4. 成果物と進捗をAIコアに返す。
5. AIペットが自分の声とキャラクターで報告し、人間がレビューして追加指示を出す。

## 現有ハードウェアと方針

- Windows自作PC：Ryzen 9 7950X、RAM 128GB、RTX 3060 12GB。ローカルLLM PoC、GPU処理、Blender、動画制作ワーカー。
- MacBook Air：M1、16GB。Xcode、iOSゲーム開発、macOSワーカー。
- Intel第11世代サーバーPC：API、DB、ジョブ管理などの候補。
- Raspberry Pi 4：ロボット側の制御・通信の候補。
- 将来のMac Studio 64GB：**購入は保留**。推論性能や同時稼働の制約が明確になったら、既存環境を置き換えるのではなく追加ノードとして検討する。

初期ローカルLLMはRTX 3060 12GBで動く4B〜8B程度の量子化モデル（例：Qwen3 8B）から実測評価する。複雑な課題はクラウド等の専門モデルに任せる。

## 段階的な実装案

1. **コアPoC**：テキスト会話、人格設定、簡単な記憶、タスク登録。
2. **分散ワーカーPoC**：WindowsとMacでそれぞれ限定的な安全なジョブを実行し、結果を返す。
3. **協業ループ**：進捗通知、レビュー、修正指示、承認、失敗時の再試行。
4. **音声・リアルタイム対話**：音声認識・合成、割り込み、短い返答、自然な反応。
5. **ロボット統合**：目、視線、ヒレ、首などの動作とコアを接続。
