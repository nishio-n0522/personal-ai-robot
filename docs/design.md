# 目PoCの設計

personal-ai-robot全体のうち、現在実装済みのブラウザ目PoCを扱う。全体構成は [architecture.md](architecture.md)、候補部品と価格・在庫は [hardware-bom.md](hardware-bom.md) を正本とする。

## 描画と状態

`EyeModel` は秒単位のdt、視線(-1〜1)、瞳孔(.25〜.7)、開き(.05〜1)、表情、瞬き命令を扱う。指数平滑化を用い、長いタブ復帰のdtは0.1秒以下に制限する。テストにはseed付き乱数を注入できる。

左右は同じモデルの視線・瞬きを共有する。開口部と寄せ方向は左右別に描画し、詳細画面は左目を表示する。頭は目より遅れて小さく追従し、体は固定する。

描画はCanvasの図形・グラデーションとCSSのみ。画像ファイルの読み込みや既存の目ライブラリの流用はない。円形表示面とまぶたの開口部を分離し、上まぶたを下へ補間して閉眼する。虹彩は上側を暗く、下側に選択色を残す。パラメータの詳細は [reference-composition.md](reference-composition.md) を参照。

ハイライトは左右とも同じ光源方向の位置・模様を使い、開口部に合わせて鏡映しない。選択した反射だけを拡大縮小し、虹彩境界とまぶたでクリップする。従来の丸パターン・標準サイズ・標準明度は既存描画を保つ。

HTTPサーバーは127.0.0.1のみで、許可した静的ファイルだけを返す。カメラ・マイクは禁止ヘッダーを付ける。外部資産なし。

## ESP32移植案

まずモデルの数式とパラメータをC++へ移す。CanvasのグラデーションはテクスチャやLUT、まぶたは走査線マスクなどで再実装し、計測する。466×466 RGB565は約434KB/フレーム、30fps全画面転送は約13MB/秒の理論量。30fpsは目標であって保証ではない。

Piから左右ESP32へsequence、単調時刻、視線、瞳孔、開き、瞬き開始時刻などを送る案。実時刻同期・通信欠落処理は未実装。

## ハードウェアの検討範囲

実2眼への移植とロボット全体の音声・カメラ・機構は未実装。型番・調達・配線・安全の判断は [部品表](hardware-bom.md) と [判断記録](decisions-risks.md) で管理し、このPoCの動作を実機適合の証拠にしない。
