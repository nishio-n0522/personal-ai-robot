# 全体アーキテクチャ案

更新: 2026-10-13。下記の実機構成は未実装。実装済みは [目のブラウザPoC](design.md) のみ。

## 責務と境界

| 層 | 主な役割 | 配置案・決定条件 |
| --- | --- | --- |
| 対話・日常支援 | STT、対話、TTS、記憶、ツールの承認 | Intel第11世代サーバーPCを候補。OS/RAM/GPU/常時稼働可否を確認し、ローカル処理と外部APIの品質・費用・送信内容を比較する。Piだけで全推論できるとは仮定しない。 |
| 身体の統括 | センサー時刻付与、追跡、状態遷移、音声入出力、接続監視 | Pi 4候補。CPU/RAM/USB帯域/温度を測り、追跡をサーバーに移す必要性を判断。 |
| 目 | ローカル描画、補間、瞬き、通信断時の静かな表情 | 左右独立ESP32-S3 AMOLED各1枚候補。完成画像の毎フレーム送信ではなく、視線等のパラメータを送る。 |
| 動作・安全 | 位置/速度制限、ウォッチドッグ、フィードバック、停止 | 専用マイコンまたは適切なサーボコントローラー候補。M5再利用は型番確認後。LLMは任意角度や電流を直接出せない。 |
| 物理保護 | ヒューズ等、配線、停止スイッチ、機械的可動域、転倒対策 | ソフト停止とは独立。電源喪失時の首落下・腕落下まで機構で考慮する。 |

## データの流れ

音声入力 → AEC後の入力 → VAD/発話区間 → STT → 対話セッション → 承認された支援処理 → TTS → **同一音響機器への再生**を基本案とする。AECの再生参照へ信号が届く実際の経路を確認し、別PCスピーカーからの再生で成立したとみなさない。割込みでは再生停止、古い生成の破棄、発話IDの更新を同時に行う。

カメラ → 人物/顔位置 → 対象選択 → 画面座標から視線座標へ変換 → 目標方向 → 目の素早い追従/首の遅い追従。本人識別用の特徴は保存しない。複数人時の選択規則、見失い時間、再捕捉、首角度によるカメラ座標補償を別に検証する。音源方向は補助候補であり、対象人物と同一と決めつけない。

押圧・IMU・接地 → デバウンス/校正 → 接触/持上げイベント → 反応選択。接地不明・持上げ時は動作制限を優先する。触れたことを本人確認やツール承認の代わりにしない。

## 通信契約案

Pi–サーバーはLAN、Pi–眼/制御器は有線USB/UART等を比較する。Wi-FiやMQTTを先に必須としない。USBポート数、ケーブル取り回し、ノイズ、復帰性からD04で決定する。

メッセージ候補: `schemaVersion, deviceId, bootId, sequence, monotonicTime, ttl, commandId, payload`。眼のpayloadは左右ID、視線x/y、瞳孔、開き、表情、色、瞬き開始時刻/長さ。アクションは許可した動作名と強度だけを受け、下位制御で範囲を検査する。受信時の値域・型・期限検証、重複/逆順排除、ACKと状態通知、再接続時の初期同期を定義する。

左右眼は共通イベント時刻を用いるが、別ESP32の時計はそのまま一致しない。時刻差推定・往復遅延・バッファ量を測り、同期ずれの受入値を決める。片眼再起動時は古い瞬きを再生せず現状態へ徐々に復帰。制御器は期限切れ命令を実行せず、安全設定の読込完了まで駆動禁止。

会話とツールは別状態機械にし、`sessionId/turnId/actionId`で追跡する。同じ承認を再利用した二重実行、タイムアウト後の無条件再送を防ぐ。結果不明なら照会/利用者への確認へ進み、勝手に再実行しない。

## 状態・運用案

起動自己診断 → 待機 → 聞く → 考える → 話すを基本に、ミュート・接続断・停止・整備を優先状態として持つ。停止時は対話が残ってもモーターを有効化しない。ネットワーク断では外部支援を中止し、手元の無害な状態表示へ移行する。

設定に機体版、配線版、各軸の校正・限界・ファーム版を記録する。音声/画像/会話本文を通常ログへ入れず、遅延、温度、電圧、エラー等を記録する案。診断用保存は明示的に有効化し、保存先・期限・削除を管理する。秘密情報はリポジトリ外へ置く。
